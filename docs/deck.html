Motivation

Why This System Exists

The Problem
  • ✕
    Research creates hundreds of artifacts — papers, notes, experiments, results — with no thread connecting them to the original question.
  • ✕
    LLMs are stateless. Great at reasoning in the moment; terrible at remembering what they concluded last week. Every session starts from scratch.
  • ✕
    Without structure, Claude will hallucinate continuity — appearing to remember context it has actually lost, or repeating work already done.
The Solution
  • ✓
    Persistent memory in files. Every insight is written down. Claude reads it fresh each session — no hallucinated continuity.
  • ✓
    A defined methodology. CLAUDE.md tells Claude exactly how to do research in this project — what structure to follow, what quality bar to meet.
  • ✓
    Automated guardrails. Hooks enforce the rules Claude might otherwise skip under pressure. The structure holds even in long sessions.
Core insight: Claude is not the researcher. Claude is the research assistant. The methodology lives in the repo — Claude executes it. This means the research process is reproducible, auditable, and improvable independently of which Claude session is running.
Without this system
Session 1: "Let's research X" → findings in chat
Session 2: Claude has no memory → starts over
Session 3: Contradicts Session 1's conclusions
Week 3: No idea what was already tried
→ Research is lost between sessions
With this system
Every session: Claude reads memory/ and CLAUDE.md
Every insight: written to memory/findings/
Every contradiction: surfaced in open-questions/
Any session: full context immediately available
→ Research compounds across sessions

Mental model

Three Primitives, One System

01
CLAUDE.md The Methodology
Guidance & flow for research
Defines what good research looks like in this project — what goes in memory, how findings are structured, what quality bar to meet, which git branches to use. Claude reads this at every session start. It's the research methodology, not code.
02
Hooks The Guardrails
Force Claude to strictly follow the methodology
Shell scripts that intercept Claude's tool calls and either block or remind. Claude can't "forget" a rule — the hook runs automatically regardless of context length or session state. Hooks encode the invariants that must never break.
03
Skills The Procedures
Detailed guidance for each operation
Step-by-step instructions for each research phase — loaded only when invoked. Skills don't define policy (that's CLAUDE.md); they define how to execute a phase: what to ask, what to write, what to log, how to commit.
What it looks like

A CLAUDE.md Template

CLAUDE.md# My Research Project

## Research Goal
What question are we answering?
What counts as done (success criteria)?

## Memory Structure
sources/       — raw material, write-once, never edited
memory/        — wiki: entities, findings, themes, questions
outputs/       — deliverables: reports, evidence, decisions

## Memory Rules
- Every page: YAML frontmatter with title, created,
  updated, confidence (high/medium/low), tags
- memory/index.md updated after every ingest
- memory/log.md is append-only — never edit past entries
- Check entity-registry.json before creating entity pages

## Quality Standards
- Every finding needs a citation + counter-argument
- Classify each finding:
    source      — directly cited from material
    analysis    — inferred; show your reasoning
    unverified  — noted but not validated
    gap         — explicitly missing information

## Git Flow
- Never commit to main
- All work on typed branches:
    research/   — new goal
    hypothesis/ — one angle on a goal
    synthesis/  — merge findings
    review/     — memory maintenance
This file IS the research methodology. Claude reads it at startup every session. It doesn't need to be reminded of the rules — they're here.
What belongs in CLAUDE.md

Rules that apply to every operation — memory hygiene, quality gates, git conventions, what counts as a finding vs. an entity.

What does NOT belong

Step-by-step procedures for specific commands. Those go in skills — loaded only when invoked, keeping CLAUDE.md focused.

The relationship

Skills reference CLAUDE.md implicitly. When /analyze says "write a finding", CLAUDE.md defines what a finding must contain.

Start minimal. Add sections only when Claude consistently gets something wrong. Every rule in CLAUDE.md should exist because something broke without it.

The routing table. Wires tool events to shell scripts. Contains no logic — only configuration.

Hook Wiring

settings.json — The Router

json{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit",
        "hooks": [{
          "type": "command",
          "command": "bash .claude/hooks/block-source-modification.sh Edit \"$TOOL_INPUT_FILE_PATH\""
        }]
      },
      {
        "matcher": "Bash",
        "hooks": [{
          "type": "command",
          "command": "bash .claude/hooks/block-commit-protected-branch.sh Bash \"$TOOL_INPUT_COMMAND\""
        }]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{
          "type": "command",
          "command": "bash .claude/hooks/post-memory-update.sh \"$TOOL_NAME\" \"$TOOL_INPUT_FILE_PATH\""
        }]
      }
    ]
  }
}
Hook Events
EventFires when
PreToolUseBefore Claude calls any tool
PostToolUseAfter a tool completes
Env Variables Passed
VariableValue
$TOOL_NAMEEdit, Bash, Write…
$TOOL_INPUT_FILE_PATHFile path (Edit/Write)
$TOOL_INPUT_COMMANDShell command (Bash)
Matcher syntax: Use | for OR — "Edit|Write" fires on either tool.
Hook Mechanics

How Hooks Control Claude

2
exit 2 — Block
The tool call is cancelled. Claude receives stderr as the error message. Only exit 2 blocks — exit 1 is a non-blocking error and execution continues.
0
exit 0 — Allow
The tool proceeds. stdout is added to Claude's context — use for reminders (PostToolUse). JSON on stdout can carry structured decisions.
1
exit 1 — Non-blocking error
Execution continues. A notice appears in the transcript but the tool is not cancelled. Not useful for enforcement.
bash — block pattern (exit 2 + stderr)#!/bin/bash
if [[ "$FILE_PATH" == *"sources/"* ]]; then
  echo "BLOCKED: sources/ are immutable." >&2
  exit 2   # ← cancels the Edit
fi
exit 0     # ← allow
bash — reminder pattern (exit 0 + stdout)#!/bin/bash
if [[ "$FILE_PATH" == *"memory/"* ]]; then
  # stdout at exit 0 → Claude's context
  echo "REMINDER: Update index.md + log.md"
fi
exit 0     # ← write still happens
Source: code.claude.com/docs/en/hooks — "Only exit 2 blocks actions. Exit 1 is treated as non-blocking error and execution continues."
Hook 1 of 3

block-source-modification.sh

PreToolUse Edit → sources/
What it does

Rejects any Edit call targeting a file under sources/.

Why it exists

Sources are the raw material of research. Once ingested, they must never change — otherwise findings that cite them become untrustworthy.

If Claude wants to "fix" a source, it should create a finding in memory/findings/ instead.

Why Edit but not Write

Write creates new files. Edit modifies existing ones. New source files are allowed; modifying them after creation is not.

bash#!/bin/bash
TOOL_NAME="$1"
FILE_PATH="$2"

# Only intercept Edit (not Write)
if [[ "$TOOL_NAME" != "Edit" ]]; then
  exit 0
fi

# Block edits to sources/ (skip .gitkeep)
if [[ "$FILE_PATH" == *"sources/"* \
   && "$FILE_PATH" != *".gitkeep"* ]]; then
  echo "BLOCKED: Source files are immutable
after creation. Create a finding in
memory/findings/ instead."
  exit 1
fi
Hook 2 of 3

block-commit-protected-branch.sh

PreToolUse Bash → git commit
What it does

Rejects git commit commands when the current branch is main.

Why it exists

All research work happens on typed branches — research/, hypothesis/, synthesis/, review/.

Committing to main directly bypasses issue-tracking and the review workflow. The hook enforces this automatically rather than relying on Claude remembering the rule.

Branch naming: hypothesis/GH-7-attention-mechanisms, synthesis/GH-5-consolidate 
bash#!/bin/bash
COMMAND="$2"

# Only intercept Bash calls
if [[ "$1" != "Bash" ]]; then
  exit 0
fi

# Check for git commit in the command
if [[ "$COMMAND" == *"git commit"* ]]; then
  BRANCH=$(git rev-parse --abbrev-ref HEAD 2>/dev/null)
  if [[ "$BRANCH" == "main" ]]; then
    echo "BLOCKED: Cannot commit to main.
Create a branch first:
  research/, hypothesis/,
  synthesis/, or review/"
    exit 1
  fi
fi
Hook 3 of 3

post-memory-update.sh

PostToolUse Edit|Write → memory/
What it does

After any file write inside memory/, prints a reminder to update memory/index.md and append to memory/log.md.

Why it exists

The index and log are the consistency layer for working memory. Without them, pages become orphans (not findable) or operations go unrecorded.

This hook ensures Claude does both in the same turn — it can't skip them and move on.

Why exit 0, not exit 1

This is a reminder, not a block. The write already happened. Claude sees the output and acts on it in the same response.

bash#!/bin/bash
TOOL_NAME="$1"
FILE_PATH="$2"

if [[ "$TOOL_NAME" != "Edit" \
   && "$TOOL_NAME" != "Write" ]]; then
  exit 0
fi

# Check for memory/ writes,
# excluding the index/log/registry
if [[
  "$FILE_PATH" == *"memory/"* \
  && "$FILE_PATH" != *"memory/index.md"* \
  && "$FILE_PATH" != *"memory/log.md"* \
  && "$FILE_PATH" != *"entity-registry.json"* \
  && "$FILE_PATH" != *".gitkeep"*
]]; then
  echo "REMINDER: memory/ was modified.
Update memory/index.md and
append to memory/log.md."
fi
exit 0   # ← never blocks

You run claude in the repo root.
Claude loads CLAUDE.md and .claude/settings.json automatically.
2
You type /research.
Claude follows skills/research.md — creates a GitHub issue, branch, goal file, and log entry.
3
You type /analyze https://….
Claude fetches the source, extracts findings + entities, writes to memory/.
4
post-memory-update.sh fires (PostToolUse → Edit).
Prints reminder. Claude updates index.md + log.md in the same turn.
5
If Claude edits sources/ — block-source-modification.sh fires, cancels the edit with an error message.
6
If Claude runs git commit on main — block-commit-protected-branch.sh blocks it.
7
You type /synthesize.
Claude reads all findings, builds themes, resolves contradictions, writes an output report.
8
Parallel agents.
Spawn multiple agents on hypothesis/ branches via Agent({ isolation: "worktree" }). Each works independently.

  • 1
    Write a shell script in .claude/hooks/. Use exit 0 to allow, exit 1 to block.
  • 2
    Register it in .claude/settings.json under the appropriate event and matcher.
bash — new hook# .claude/hooks/block-direct-output-write.sh
if [[ "$FILE_PATH" == *"outputs/"* ]]; then
  echo "BLOCKED: Use /evidence, /verify,
/examples, or /critique to produce
outputs — not direct Write."
  exit 1
fi
json — wire it in settings.json{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write",
        "hooks": [{
          "type": "command",
          "command": "bash .claude/hooks/block-direct-output-write.sh Write \"$TOOL_INPUT_FILE_PATH\""

      }
    ]
  }
}
Hooks run as the current user with access to the full shell environment. Keep them fast — they run on every matching tool call.

New skill

/import — Bring In an Existing Project

/analyze ingests one source at a time. /import bulk-ingests a whole project in one pass — maps the structure, classifies artifacts, builds memory.
  • 1
    Accepts local path, git URL, or glob — ../my-project, https://github.com/org/repo, ./docs/**/*.md
  • 2
    Classifies artifacts into tiers — Primary docs, Code, Data, Config, Skip. Copies Primary + Code to sources/<slug>/.
  • 3
    Extracts entities and findings from READMEs, notebooks, design docs, comments — with verification gates + FUNGI counter-arguments.
  • 4
    Mines open questions from TODO/FIXME comments, "Future Work" sections, skipped tests, missing docs.
Artifact Tiers
TierWhatAction
PrimaryREADMEs, notes, notebooks, papersCopy + deep analysis
CodeSource files (.py, .ts, …)Copy key files + summarize
Configpyproject.toml, YAML, package.jsonCopy + extract deps
DataDatasets, CSVs, large filesPointer file only
Skip.git/, node_modules/, __pycache__/Ignore

/import ../my-existing-project

# Git repo (cloned to /tmp/ first)
/import https://github.com/org/repo

# Just the docs
/import ./my-project/docs/**/*.md

# After import, continue with:
/analyze      # deep-dive a specific file
/research     # define a goal around it
/import — step by step

/import — How It Works

1
Resolve & inspect the source. List the directory or clone the git repo to /tmp/import-<slug>. Build a map of file types and sizes.
2
Classify artifacts into tiers. Primary docs → deep analysis. Code → architecture summary. Data → pointer stub. node_modules/, .git/ → skipped.
3
Copy to sources/<slug>/ with a MANIFEST.md listing every file imported and every file skipped (with reason). Sources are immutable after this step.
4
Extract entities. Check entity-registry.json before creating. Tools, libraries, models, datasets, authors — each gets a page in memory/entities/.
5
Extract findings from READMEs, notebooks, design notes, and code comments. Every finding gets a verification gate (source / analysis / unverified) and a FUNGI counter-argument.
6
Mine open questions from TODO/FIXME comments, "Future Work" sections, skipped tests, and missing documentation. Each goes to memory/open-questions/.
7
Update memory index & log. All new pages catalogued in memory/index.md. The full operation appended to memory/log.md.
8
Optionally create a research goal. If you want a structured research branch around the imported project, /import can hand off to /research automatically.
After /import, use /analyze to deep-dive any specific file, or /experiment if the project has ML training code.
